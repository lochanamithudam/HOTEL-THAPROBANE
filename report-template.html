01 Executive Summary

A thorough static analysis and code review was conducted across the backend ecosystem of Hotel Thaprobane, comprising both the dedicated Express server (server.js), local diagnostic utilities (test-backend.js, send-test-email.js), and the Vercel serverless cloud endpoints (api/bookings.js, api/subscribe.js, api/test-email.js, api/_lib/db.js).

While the dual-architecture (Express + Serverless fallback) and offline JSON persistence mechanism display thoughtful fault-tolerance, several critical bugs exist that lead to silent data loss in MongoDB, runtime process crashes on malformed requests, and broken serverless connection caching.

02 Critical Runtime & Data Integrity Findings
1. Unhandled Request Body Destructuring Causing Crash (TypeError)
Critical Bug
api/subscribe.js : Line 11  |  server.js : Line 546
When an incoming HTTP POST arrives without an explicit JSON content-type header or with an empty payload, req.body evaluates to undefined. Destructuring directly causes an unhandled TypeError.
// Vulnerable code: const { email } = req.body; // Throws: TypeError: Cannot destructure property 'email' of 'req.body' // Required safe handling: const email = req.body?.email; if (!email || typeof email !== 'string' || !email.includes('@')) { return res.status(400).json({ success: false, message: 'Valid email required' }); }
Fix: Add optional chaining (req.body?.email) and verify body existence before processing.
2. Silent Data Loss: "roomName" Missing from Mongoose Schema
Data Loss
api/_lib/db.js : Lines 26–40  |  server.js : Lines 81–94
The frontend reservation modal in js/app.js submits the room title as roomName. However, the Mongoose schema only declares roomCategory: String. Under Mongoose default strict: true mode, unmapped fields are quietly discarded upon document persistence.
// Schema definition in db.js & server.js: const bookingSchema = new mongoose.Schema({ roomCategory: String, // Declared /* roomName is missing! Dropped during new Booking(data).save() */ checkIn: String, ... });
Fix: Explicitly declare roomName: String in both api/_lib/db.js and server.js schemas.
3. "bookingRef" Not Declared in server.js Mongoose Schema
Data Loss
server.js : Lines 81–94 & Line 221
In server.js, line 221 creates new Booking({ ...bookingData, bookingRef }), but bookingRef exists only in api/_lib/db.js schema and is absent from server.js schema. When running via Express locally, reference numbers (e.g., HT-849201) are never recorded in MongoDB.
Fix: Add bookingRef: String to server.js booking schema.
03 Architecture, Serverless & Environment Findings
4. Serverless Mongoose Connection Reuse Caching Bug
Performance & Scale
api/_lib/db.js : Lines 5, 8, 18
The variable let cached = global._mongooseConnection; is set once at module load time when global._mongooseConnection is undefined. Even though line 18 sets global._mongooseConnection = true, the local variable cached remains permanently undefined in that scope. As a result, warm serverless invocations fail to skip redundant connections.
// api/_lib/db.js current logic: let cached = global._mongooseConnection; // Evaluated once as undefined async function connectDB() { if (cached && mongoose.connection.readyState === 1) return; // Always false! await mongoose.connect(uri); global._mongooseConnection = true; }
Fix: Test if (mongoose.connection.readyState === 1) return; directly without relying on an un-updated local closure.
5. Missing dotenv Injection in Serverless Handlers
Configuration
api/ Directory : All Handlers & api/_lib/db.js
require('dotenv').config() is called only inside server.js. If a developer runs node api/test-email.js or invokes serverless functions in standalone test harnesses, all environment variables (MONGO_URI, GMAIL_USER, GMAIL_PASS) evaluate to undefined.
Fix: Add safe if (process.env.NODE_ENV !== 'production') try { require('dotenv').config(); } catch(e){} at top of api/_lib/db.js.
6. Mongoose OverwriteModelError on File Watcher / Reload
Stability
server.js : Line 96
server.js compiles Booking directly with mongoose.model('Booking', bookingSchema), whereas Subscriber correctly uses mongoose.models.Subscriber || mongoose.model(...). Any re-execution throws OverwriteModelError.
Fix: Change line 96 to const Booking = mongoose.models.Booking || mongoose.model('Booking', bookingSchema);.
7. Hardcoded Global DNS Server Override
Network Reliability
server.js : Lines 1–6
Forcing dns.setServers(['8.8.8.8', '8.8.4.4']) overrides OS, corporate, and VPN resolver tables. In networks where port 53 is intercepted or firewalled, Atlas SRV records (mongodb+srv://) fail to resolve completely.
Fix: Remove hardcoded DNS override or gate it behind an explicit debug environment flag.
8. Email Template HTML/XSS Injection Vector
Security Polish
api/bookings.js : Lines 95, 114–177  |  server.js : Lines 320–420
Unescaped user input (such as guest name and phone) is interpolated directly into outgoing HTML emails. While modern email clients sanitize script tags, unescaped quotes and markup can corrupt email layout or allow malicious link injection.
Fix: Pass user values through a basic HTML entity sanitizer (&amp;, &lt;, &gt;) before injecting into email templates.

05 Remediation Priority Checklist

  • Remove or conditionally enable the hardcoded Google DNS override in server.js.
