01 Executive Summary & Re-Assessment Overview

Following the initial security audit, significant architectural hardening has been successfully applied to the Hotel Thaprobane web infrastructure. Crucially, both previous High-Risk vulnerabilities have been completely eradicated from the active application codebase:

  • SEC-02 (Eliminated): The hardcoded diagnostic fallback key (thaprobane_admin_2026) was removed from both server.js and api/test-email.js. Strict, fail-closed validation now ensures arbitrary mail relaying is impossible.
  • SEC-03 (Eliminated): Unvalidated X-Forwarded-For parsing has been replaced by native Express reverse proxy trust (app.set('trust proxy', 1)). Remote attackers can no longer spoof local loopback IPs (127.0.0.1) to bypass rate limits or authentication.
  • SEC-07 (Eliminated): offline_bookings.json has been systematically added to .gitignore and .vercelignore, mitigating guest PII exposure during emergency failover events.

The application security posture has elevated from Grade C+ (68/100) to Grade B+ (84/100). One Critical item remains related to secret hygiene in historical Git commits, which requires token revocation in Google Account.

03 Verified Fixes & Architecture Hardening
RESOLVED & VERIFIED SEC-02: Hardcoded Admin Key & Arbitrary Mail Relay
Was High (CVSS 7.5)
Affected Files: server.js:794-806 & api/test-email.js:14-24

Previous Risk: The diagnostic endpoint had a fallback key 'thaprobane_admin_2026' and an IP bypass allowing attackers to relay spam emails to any arbitrary recipient worldwide.

Verification Result: Fully Hardened. Hardcoded string was eradicated. Strict fail-closed logic now enforces that unless process.env.ADMIN_KEY matches explicitly, test emails can only be delivered to the verified hotel admin address (lochanamithudam097@gmail.com).
// Verified Live Implementation in server.js & api/test-email.js: const configuredAdminKey = process.env.ADMIN_KEY; let targetEmail = adminEmail; if (requestedEmail && requestedEmail !== adminEmail) { // Fail-closed: No fallback secrets, no IP bypass if (!configuredAdminKey || adminKey !== configuredAdminKey) { return res.status(403).json({ success: false, message: 'Forbidden: Test email can only be dispatched to the verified administrator address.' }); } targetEmail = requestedEmail; }
RESOLVED & VERIFIED SEC-03: Client IP Header Spoofing via Unvalidated X-Forwarded-For
Was High (CVSS 7.3)
Affected Files: server.js:19-23 & server.js:50-53

Previous Risk: Unvalidated user input from req.headers['x-forwarded-for'] allowed clients to inject 127.0.0.1 to spoof loopback origins, reset rate limiter thresholds, and bypass diagnostic safeguards.

Verification Result: Fixed via Reverse Proxy Configuration. Express is now configured with app.set('trust proxy', 1), delegating IP resolution securely to the first trusted upstream proxy hop (Cloudflare/Nginx/Vercel) via native req.ip.

RESOLVED & VERIFIED SEC-07: Offline Bookings PII Leakage Risk
Was Low (CVSS 4.2)
Affected Files: .gitignore:9 & .vercelignore:7

Previous Risk: The fallback file offline_bookings.json (used to store guest bookings when MongoDB is unreachable) was not listed in .gitignore, posing a high risk of committing guest full names, emails, and phone numbers into public version control.

Verification Result: Fixed. offline_bookings.json is now strictly ignored in both .gitignore and .vercelignore, ensuring guest PII will never be tracked or bundled into cloud deployments.

04 Open Findings Requiring Action
CRITICAL · CVSS 9.1 SEC-01: Plaintext App Password in Git History
Action Needed
Target: Git Commit History (Commit 7bfc0dd) · Secret: gljguakkenemhrkz

An active Google App Password was previously recorded in Git commit 7bfc0dd. While current working trees use environment variables, anyone with read access to the Git repository history can recover the key.

Business Impact: Total takeover of the hotel's Google Workspace / Gmail account. Attackers could read guest inquiries, intercept booking confirmations, or issue spam campaigns.
Required Immediate Action:
  1. Visit Google Account > Security > App Passwords and immediately Delete/Revoke the key gljguakkenemhrkz.
  2. Generate a new 16-character App Password and update the local .env and Vercel environment secrets.
  3. Purge Git history using git-filter-repo or BFG if the repository is ever pushed to GitHub/GitLab.
MEDIUM · CVSS 6.1 SEC-04: Permissive CORS with Reflected Origins & Credentials
Action Needed
Target: server.js:84-99 & api/_lib/db.js:64

In server.js, CORS callback passes callback(null, true) for all origins with credentials: true. In api/_lib/db.js, Access-Control-Allow-Origin: * is set.

Recommended Hardening: Restrict CORS to explicit production domains (e.g., https://hotelthaprobane.com and authorized Vercel preview domains).
MEDIUM · CVSS 5.9 SEC-05: Disabled TLS Certificate Validation (SMTP Transport)
Action Needed
Target: server.js:211 & api/_lib/db.js:59 (rejectUnauthorized: false)

The Nodemailer configuration explicitly disables certificate trust verification (rejectUnauthorized: false). This exposes SMTP credentials to Man-in-the-Middle (MITM) attacks on untrusted networks.

Recommended Hardening: Remove rejectUnauthorized: false. Google SMTP uses well-known, trusted Root CA certificates.
MEDIUM · CVSS 5.4 SEC-06: Unsanitized Input in Email Templates (HTML Injection)
Action Needed
Target: server.js:405 (Ayubowan, ${bookingData.guestName}) & api/bookings.js

User-supplied strings from booking payloads are concatenated directly into HTML email templates without HTML entity encoding, creating risks of HTML injection and link spoofing in guest/admin email clients.

Recommended Hardening: Wrap all dynamic user inputs in an HTML entity encoder (e.g., replacing <, >, ", ', &).

05 Positive Security Controls Already Active

🛡️ Reverse Proxy Trust & Anti-Spoofing

Configured with app.set('trust proxy', 1). Protects all rate limiting logic and guarantees authentic client IP resolution across Cloudflare and Vercel.

🔒 Fail-Closed Diagnostic Auth

ADMIN_KEY is strictly enforced for mail tests. No hardcoded credentials exist, and unauthorized outbound mail relaying is completely blocked.

📦 Strict Payload Limits (DOS Defense)

express.json({ limit: '100kb' }) prevents memory exhaustion and large-payload buffer denial-of-service attempts.

🔑 Atlas Password Masking in Logs

Connection strings automatically sanitize database credentials with regex masking (:****@), preventing credential leakage in cloud logging.

🛡️ Helmet HTTP Security Headers

Enforces X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, and baseline CSP protections against clickjacking and MIME sniffing.

✅ Zero Dependency Vulnerabilities

npm audit confirms 0 vulnerabilities across 122 production and development dependencies (Express 5.2.1, Mongoose 9.9.4, Helmet 8.3.0).
